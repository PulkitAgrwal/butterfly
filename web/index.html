How it works

01

Turn the run into a graph

Every message becomes a step. When a later step reuses a URL, file, number or name from an earlier one, follows its instruction, or reads its output, Butterfly links them. No LLM involved.

02

Let FalkorDB rank the suspects

Graph queries score every step by how much of the run builds on it, how many new facts it introduced, and how early it happened. Most of the work ends here.

03

One LLM call, then the chain

A model reads only the top suspects and picks the decisive one. A shortest-path query then looks for the chain from the failure back to the mistake, so the answer can be checked when the graph links them.

Built on FalkorDB

  • One graph per run. Each failure is its own isolated graph, created and queried in milliseconds.
  • Graph algorithms as tools. Breadth-first search measures how far a mistake spreads; shortest paths link the failure back to it.
  • Safe by default. Every read is a read-only query with a timeout, and every import is safe to re-run.
  • Answers you can check. When the graph links a mistake to the failure, the link is a Cypher path, not a paragraph.
// The proof: from the failure back to the suspect
MATCH (f:Step {is_final: true}), (s:Step {idx: $idx})
WITH shortestPath((f)-[:DEPENDS_ON*]->(s)) AS p
RETURN [n IN nodes(p) | n.idx] AS steps

// How much of the run builds on each suspect
MATCH (s:Step {candidate: true})
CALL algo.BFS(s, 200, 'FEEDS') YIELD nodes
RETURN s.idx, size(nodes) AS downstream
